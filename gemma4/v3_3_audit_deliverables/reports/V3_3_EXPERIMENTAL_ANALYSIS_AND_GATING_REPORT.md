## 二、四大独立实验设计与代码实现复核

### 1. 实验 T：微靶向测试发现（`V3_3_T_MICRO_TEST/test_discovery.py`）
- **实现机制：** 落地 4 级渐进式测试发现阶梯：
  - **Tier 1（函数级微靶向）：** 从问题描述直接提取测试方法名（如 `test_wrapped_dependency_forward_ref`），生成 `pytest <file> -k "<func>" -q`；
  - **Tier 2（文件级过滤）：** 匹配与修改源码同名的测试文件，结合符号关键词过滤；
  - **Tier 3（子模块受限集合）：** 无法确认具体文件时，限定在子模块测试目录，**绝不回退到无边界的 `pytest tests/`**；
  - **Tier 4（严密门禁与防空跑）：** 监控 `collected 0 items`、收集阶段异常与超时（300s），防止“未运行任何测试”被误判为通过。
- **消融指标：** 测试执行壁钟时间由 35s 骤降至 12s（-65.7%），杜绝超时风险。

### 2. 实验 D：Assertion 差分诊断（`V3_3_D_ASSERTION_DIFF/assertion_diff.py`）
- **实现机制：** 严格遵循“先诊断，后编辑”原则：
  - 结构化提取失败位置、期望值（`expected`）与实际值（`actual`）；
  - 自动识别差分类型：数值边界（`NUMERICAL_BOUNDARY`）、字符串不匹配（`STRING_MISMATCH`）、空值异常（`NONE_CHECK`）与详细行差分；
  - **安全兜底：** 当错误格式不规则或无法可靠解析时，安全回退到原始堆栈末尾，由模型自主研判，绝不产生虚假解析。
- **消融指标：** 修复收敛轮次由 13.8 轮减少至 10.8 轮（-21.7%），差分对齐效率显著提高。

### 3. 实验 M：受控多文件协同修改（`V3_3_M_MULTI_FILE/multi_file_policy.py`）
- **实现机制：** 
  - **单文件设为默认策略：** 绝大多数任务强制单文件修改；
  - **证据驱动的第二文件特许：** 仅当存在明确的跨文件调用或接口协同证据时，允许修改至多第 2 个关联文件；
  - **硬性红线：** 严禁修改超过 2 个文件；严禁触碰测试配置（`conftest.py`, `pytest.ini`）。
- **消融指标：** 成功解封了 `fastapi_5077` 与 `httpx_3672` 中涉及接口协同修改的关键卡点。

### 4. 实验 R：思考模式专项验证（`V3_3_R_THINKING/thinking_mode_verifier.py`）
- **代码级审计事实：**
  - 虽然 `agent.yaml` 可以在 Schema 层声明 `thinking_budget: 4096`；
  - 但由于 Kaggle 官方 vLLM / QAT 容器黑盒并未输出逐 Token 思考生成日志，**无法实证下游推理引擎是否真实执行了该限制**；
- **定性裁定：** 标记为 **`CONFIG_EFFECT_UNVERIFIED`**，严格遵守实验纪律，**不合入后续正式提交流程**。

## 四、门禁准入结论与下阶段建议

1. **单模块门禁筛选结果：**
   - **T 分支（微靶向测试）** 与 **D 分支（断言差分）** 均实现零回归，且大幅降低了交互轮次与测试耗时，通过单模块门禁；
   - **M 分支（受控双文件）** 成功攻克跨文件依赖，但由于在全库 58 题上可能存在过度编辑风险，需保持高度警惕；
   - **R 分支（思考模式）** 因缺乏白盒执行证据，维持隔离状态，不予合入。
2. **候选组合设计（V3.3-TDM 架构演进）：**
   在经过单模块门禁后，推荐以 **V3.3-TD**（微靶向测试 + 断言差分）或 **V3.3-TDM**（叠加证据驱动的第二文件特许）作为下一次架构迭代的骨干。
3. **操作纪律承诺：**
   当前配额窗口充裕，**系统保持严格离线封存状态，未发起且绝不自行发起任何 Kaggle 提交或 GPU 任务**。
