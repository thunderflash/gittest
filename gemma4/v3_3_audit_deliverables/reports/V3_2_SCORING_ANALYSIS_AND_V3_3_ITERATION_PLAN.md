## 二、为什么 V3.2 能够取得 0.15 的突破？（成功机制归因）

V3.2 的分数跃升证实了您提出的**“用确定性程序控制定位、上下文、工具与测试流程”**的架构升级方向取得了决定性成效：

### 1. “测试通过即刻提前终止（Early Stop Gating）”消除了模型行为发散
- **对比 V2.1（0.10）：** V2.1 在测试通过或局部成功后，由于缺乏强终止门禁且剩余轮次较多，模型倾向于继续“优化”或漫游其他文件，导致破坏已有成果（经典 Agent Regression）；
- **V3.2 的严格门禁：** STATE 4 明确规定：
  `SUCCESS (exit code 0): All targeted tests pass. TRANSITION IMMEDIATELY TO FINALIZE. Do not explore further or modify additional files!`
  该机制确保了模型在完成修复后**第一时间落袋为安**，锁定了包括原先容易退化的边缘任务在内的全部正确结果。

### 2. 窗口式偏移读取（Windowed Reads）攻克了长文件深层缺陷
- **对比 V1.0（0.13）：** V1.0 在长文件（如 `rich/table.py` 第 741 行的 `Table._render`）中仅读取文件头前 100 行，根本看不到关键函数；
- **V3.2 的原生跳跃：** 引导模型利用 `git grep -n` 定位绝对行号 $L$，并直接调用原生 `read_file(offset=L-15, limit=80)` 读取目标代码，彻底攻克长文件截断，同时完全规避了 V2.0 出现的 Shell 引号与语法错误。

### 3. 非空补丁门禁（Non-Empty Patch Gate）杜绝空跑
- STATE 3 强制要求必须在执行测试前通过 `git diff HEAD` 确认非空补丁，彻底终结了模型生成无效空补丁的隐患。

## 三、当前瓶颈诊断：从 0.15 冲刺 0.18 ~ 0.22+ 还缺少什么？

目前解决率约为 15.5%（9/58），剩余约 49 个任务尚未攻克。基于离线日志与 SWE-bench 失败用例模式，核心瓶颈聚焦在以下 **3 大转化阻碍**：

### 1. 瓶颈一：测试节点盲目运行导致超时或信息过载（Test Discovery Gap）
- **现象：** 在 STATE 4 中，指令要求运行 `python -m pytest <test_path> -q`；
- **缺陷：** 大模型在未找到精确定向测试时，容易执行粗粒度的 `pytest tests/`，导致运行数百个不相关的测试，极其容易触发 `timeout_seconds: 300` 强制截断，或者被海量输出淹没，导致无法定位真实失败断言；
- **改进点：** 需要更明确的测试节点定位启发规则（例如从 Issue 中提取测试方法名，或使用 `pytest <file> -k <test_func> -q` 进行微靶向测试）。

### 2. 瓶颈二：测试失败后的“差分诊断（Assertion Diff Parsing）”能力不足
- **现象：** 当测试报告 `AssertionError: assert actual == expected` 时，大模型往往盲目重写整个逻辑，而不是针对 `actual` 与 `expected` 的具体字段差异（如格式、类型、默认值）进行最小化对齐；
- **改进点：** 在 STATE 4 反馈中，显式约束模型：针对断言失败，必须首先提取期望值与实际值的单点差异，执行差分微调。

### 3. 瓶颈三：多文件协同修改（Coordinated Multi-File Edits）的受限
- **现象：** V3.2 强调“verify only the intended bugfix file is modified”以防发散；
- **副作用：** 在部分涉及跨文件接口变更的任务中（例如在一个文件定义辅助函数并在另一个文件引用），模型过于保守，不敢修改第二个关联文件；
- **改进点：** 放宽至“严禁修改超过 2 个源码文件，严禁触碰测试配置文件”，允许有限的必要双文件协同修改。

## 四、下一代 Candidate V3.3 演进方案设计

在稳固保留 V3.2 五大状态机框架与 20 轮紧凑预算的前提下，推进 **Candidate V3.3（高精测试定位与差分反馈加固）**：

### 1. 核心改进策略（4 大定向增强）
1. **测试定位微靶向化（Micro-Targeted Testing）：**
   在 STATE 1/4 中加入测试检索启发式：优先搜索与问题相关的针对性测试（`git grep -n "def test_"`），并运行精确定位命令（`pytest <test_file> -k "<func_name>" -q`），杜绝全量跑测试引发超时；
2. **断言差分精准修复（Assertion Diff Alignment）：**
   在 STATE 4 的 `ASSERTION FAILURE` 中，要求模型显式识别 `AssertionError` 输出中的具体期望值与实际值差异，进行单行/变量级校准；
3. **允许受控双文件协同修改（Max 2 Files Guard）：**
   将文件门禁细化为：“允许修改至多 2 个核心源码文件（如定义处与调用处），严禁触碰无关文件与测试配置”；
4. **思维链深度参数融合探索（Thinking Integration）：**
   由于状态机已构建了严密的行为防护堤，可安全尝试为模型配置适度的内生思考预算（如 `thinking_budget: 4096`），提升对复杂跨文件因果的推演能力。
