## 2. 执行总原则

1. **已提交版本只读。** 不修改 V1.0、VNext 的压缩包、manifest、配置、Notebook 或原始证据。
2. **禁止隐式重投。** 失败、超时、无分数或状态不明时，先保存证据并分类；不自动重试、不换名重投、不创建额外 Kaggle 提交。
3. **评分等待不等于后台授权。** 不宣称持续轮询。若外部执行编排器负责监测，只允许按既有许可做只读状态检查并留存原始回执。
4. **只在独立工作区修改。** 下一代原型放在独立的 `worktrees/`、分支或实验目录；不得让并行 Agent 写入同一目录。
5. **结论按证据分级。** 区分离线指标、合成测试、Harness 端到端证据和 Kaggle 官方得分，不把前者直接等同于后者。
6. **正式提交需单独授权。** 本文的下一轮评分计划仅定义门槛，不等于用户批准执行。

## 3. 并行工作包

### Agent A — 两个正式提交的只读差异审计

**目标：** 搞清楚 VNext 相对 V1.0 实际增加了什么，新增代码是否可执行、是否被 Agent 调用。

**任务：**
- 取得两份提交的原始 ZIP 或可靠镜像，重算 SHA-256；与台账比对。
- 输出逐文件差异清单：新增、删除、修改、大小、哈希、入口引用。
- 检查 `agent.yaml`、主提示词、子 Agent、Skill、执行脚本和配置之间的调用关系。
- 明确标记每项新能力为 `PRESENT_AND_REFERENCED`、`PRESENT_BUT_UNREFERENCED`、`MISSING` 或 `UNVERIFIED`。
- 检查提交包路径、相对引用和依赖是否能在正式沙箱内解析。

**交付物：** `A_SUBMISSION_DIFF_REPORT.md`、`A_FILE_DIFF.csv`、`A_ENTRYPOINT_MAP.json`。

**停止条件：** 缺少原始提交包或可靠的同源镜像时，不能推断提交代码内容；记录 `UNVERIFIED`，不得根据报告摘要补造文件差异。

### Agent B — Graph / Fusion 模块回归与对照

**目标：** 验证词法、图关系与候选融合在离线定位上的实际表现，并守住历史负例。

**任务：**
- 复现既有 Graph-on-Lexical、Lexical、Lexical+Graph/Fusion 对照结果。
- 检查排序公式、分数归一化、tie-break 规则和候选并集，确认强词法证据不会因无图证据被错误清零。
- 将 `requests_6589:super_len` 作为强制回归案例，记录 lexical rank、graph rank、fusion rank 和各项原始分数。
- 用五任务离线 cohort 逐任务报告 file/symbol HIT@1、HIT@5、Recall@5、MRR 和有效样本数；不得只报宏平均。
- 检查历史所谓符号 HIT@5 `10.53% → 52.63%` 的分母、排名计算、截断和复现方式。

**交付物：** `B_GRAPH_FUSION_AUDIT.md`、`B_LOCALIZATION_METRICS.csv`、可复现测试及运行命令。

**边界：** Graph 结果只支持离线定位判断；不据此直接宣称 Kaggle repair score 会提升。纯 Graph 模式默认保持为对照，不自动取代词法路径。

### Agent C — AST Context Builder 与上下文必要性审计

**目标：** 验证 AST 符号正文提取是否正确，以及构建器对目标正文、调用关系、测试内容与预算的处理。

**任务：**
- 使用固定输入复核 AST 解析、符号定位、行号、函数正文和异常回退。
- 检查目标函数较晚出现在文件中的情形，回归 `rich_2725` 目标函数遗漏问题。
- 记录目标正文、必要 caller/callee、类型声明和相关测试是否进入 context，分别统计，不将文件命中当成符号命中。
- 核查重复文本、截断策略、token/字符预算估计、无效定位和多符号同名歧义。
- 明确 `100% target-body coverage` 是在何种输入条件下得出；若使用 gold 定位，只能标为条件性上下文测试，不能当作生产 Agent 的自主定位成功率。

**交付物：** `C_CONTEXT_BUILDER_AUDIT.md`、`C_CONTEXT_COVERAGE.csv`、回归测试。

### Agent D — Official Harness / 打包兼容性审计

**目标：** 证明新增模块可以在竞赛运行环境中加载与执行，而不是只在开发机可用。

**任务：**
- 对照当前可用的官方规则、Harness 接口和提交说明检查入口与目录要求。
- 检查 `agent.yaml`、`!include`、Skill、子 Agent、工具声明、脚本权限、相对路径与运行时依赖。
- 验证所有提交内脚本仅使用允许的本地运行能力和官方暴露工具；不假设本地文件系统、依赖或网络 API 在沙箱内同样可用。
- 在副本上解压最终 ZIP，从 ZIP 自身执行配置解析和冒烟测试。
- 输出模块加载与调用轨迹，证明新增 Fusion / Context Builder 的返回值确实进入后续 Agent 决策链。

**交付物：** `D_HARNESS_PREFLIGHT_REPORT.md`、`D_PREFLIGHT_CHECKLIST.csv`、可复现冒烟测试日志。

**停止条件：** 不向 Kaggle 远端提交、不启动 GPU，不修改正式已提交文件。

## 4. 并行管理与合并规则

- Agent A、B、C、D、E 各自使用独立目录和独立输出文件；只允许 Agent A 管理提交包静态差异报告，不允许任何 Agent 改动两个正式提交包。
- 共用原始输入均视为只读；不得在工作副本之外格式化、重打包或覆盖证据。
- 各 Agent 必须附上使用的文件版本、SHA-256、命令、测试数量、通过/失败数、未解决项和结论限制。
- “没有找到证据”必须记录为 `NOT_FOUND` / `UNVERIFIED`，不可写成 PASS。
- 主协调者只合并报告，不在没有证据的情况下合成结论。
- 若两个报告对同一事实冲突，建立 `CONFLICT_REGISTER.md`，记录双方证据、时间与待裁定项。

## 5. VNext 评分返回后的决定矩阵

先确认提交终态和分数，再应用以下规则：

| 结果 | 必需诊断 | 决策 |
|---|---|---|
| `COMPLETE` 且分数高于 `0.13` | 复核分数、提交哈希、评测可比性；检查 A-D 证据是否与改善机制一致 | 保留 VNext 候选；下一轮只选择一个主要变量 |
| `COMPLETE` 且分数约等于 `0.13` | 核查模块是否执行，Fusion 排序是否进入决策，上下文变化是否影响生成，Verifier 是否通过 | 先找转化瓶颈；不要同时添加更多模块 |
| `COMPLETE` 且分数低于 `0.13` | 检查定位回归、AST 错误、上下文过大/缺失、工具调用和预算轨迹 | 隔离负收益模块；可在离线副本回滚对照，正式提交另行授权 |
| 终态失败、无分数或输出不完整 | 保存原始报错，区分配置、基础设施、Harness 与 Agent 失败 | 停止；不自动重投或换名提交 |
| 状态仍为 `PENDING` / `RUNNING` | 保存本次只读快照及观测时间 | 继续本地审计，不推断成绩 |

`0.18`、`0.22` 等数字只能是事先设定的目标，不是预测或验收事实。只有实际官方分数出现后才能计算增量。

## 6. 下一轮候选实验：单变量优先

只有在 VNext 终态已知、A-D 报告合并完成后，才决定下一轮变更。优先考虑如下顺序：

1. **如果混合排序没有实际接入：** 修复工具/脚本调用链；其他策略保持不变。
2. **如果混合排序已接入但出现候选回归：** 只调 Fusion 证据融合或候选保留规则；Context Builder 不变。
3. **如果候选定位已改善但目标代码正文缺失：** 只优化 AST/context 选择和截断，不改排名权重。
4. **如果定位与上下文质量都改善但 repair score 持平：** 分析代码推理、最小补丁、测试顺序、轮次消耗和验证行为；下一轮只选择一个可度量假设。
5. **只有基线稳定且有实验依据后：** 才讨论更复杂 Scheduler、额外 Agent、LoRA 或其他大范围改造。

每个候选需提前写明：假设、唯一主要变量、固定项、离线测试、成功阈值、回归门槛、停止条件和是否需要新的提交授权。若无有效证据，不进入正式提交。

## 7. 评分对比指标

### 主指标
- Kaggle Official Public Score（仅在提交 `COMPLETE` 且分数有效时记录）。
- `delta_public = score_vnext - score_v1.0`。
- 若官方页面说明评分按仓库验证 PASS 比例计算，可额外记录可确认的通过仓库数和总仓库数；否则不要推导未公开的细项。

### 诊断指标
- 实际检索调用数、融合模块调用次数、目标符号在候选中的排名。
- 目标函数正文与相关测试正文覆盖率。
- 非空补丁比例、官方 Verifier 触发率、最终 PASS/FAIL。
- 预算耗用、被拒工具请求、超时及基础设施状态。

### 解释边界
- 离线 HIT@K、MRR 和正文覆盖率是诊断指标，不是 Kaggle 评分的替代品。
- 单个公开分数不能证明某个模块具有因果收益，尤其在多个模块一起变更时。
- 公开得分与私有最终成绩应分开记录。

## 10. 本阶段停止条件

遇到以下任一情形即停止相应工作并汇报：

- 正式提交文件、版本哈希或关键原始证据缺失；
- 模块实现与正式配置之间无法证明存在调用关系；
